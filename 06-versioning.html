语义化版本规范 ​

版本号格式：MAJOR.MINOR.PATCH ​

字段含义变更场景示例
MAJOR主版本不兼容的 API 变更1.0.0 → 2.0.0
MINOR次版本向下兼容的功能新增1.0.0 → 1.1.0
PATCH补丁向下兼容的问题修复1.0.0 → 1.0.1

预发布版本 ​

标识含义示例使用场景
alpha内部测试1.0.0-alpha.1功能开发中，不稳定
beta公开测试1.0.0-beta.2功能基本完成，待反馈
rc候选发布1.0.0-rc.1即将正式发布，仅修复 bug

版本范围符号 ​

符号含义示例等价范围
^兼容版本^1.2.3>=1.2.3 <2.0.0
~近似版本~1.2.3>=1.2.3 <1.3.0
>=最低版本>=1.2.3无上限
=精确版本=1.2.3仅 1.2.3
*任意版本*所有版本

Changesets 核心概念 ​

什么是 Changesets？ ​

Changesets 是一个用于管理 monorepo 版本与变更日志的工具，核心思想是：

  • 每个变更都显式声明：开发者创建 changeset 文件描述本次改动
  • 自动计算版本：根据 changeset 类型自动决定 bump 级别
  • 自动生成 CHANGELOG：汇总所有 changeset 生成发布日志

安装与初始化 ​

bash
# 安装
pnpm add -Dw @changesets/cli

# 初始化
pnpm changeset init

Changeset 文件结构 ​

markdown
// .changeset/wise-pandas-dance.md
---

'@tutorial/ui': minor
'@tutorial/utils': patch
---

feat: 新增 Button 组件 loading 状态
fix: 修复 utils 中 deepClone 循环引用问题

变更类型映射 ​

Changeset 类型版本 bump适用场景
majorMAJOR +1破坏性变更（breaking change）
minorMINOR +1新功能（feature）
patchPATCH +1修复（fix）、文档（docs）

版本发布流程 ​

完整流程 ​

bash
# 1. 创建 changeset（每次功能开发后）
pnpm changeset

# 交互式选择：
# - 哪些包受到影响？
# - 变更类型（major/minor/patch）？
# - 变更描述？

# 2. 版本计算（合并所有 changeset）
pnpm version
# 或 pnpm changeset version

# 自动执行：
# - 更新 package.json 版本号
# - 生成 CHANGELOG.md
# - 删除已消费的 changeset 文件

# 3. 发布到 registry
pnpm release
# 或 pnpm changeset publish

# 自动执行：
# - 构建所有包
# - 替换 workspace:* 为真实版本号
# - 发布到 npm
# - 创建 git tag

发布前检查清单 ​

bash
# 检查 workspace 依赖是否已替换
pnpm publish --dry-run

# 检查包内容
pnpm pack --dry-run

版本同步策略 ​

固定版本模式（Fixed） ​

所有包使用相同版本号，任何变更触发全量发布：

json
// .changeset/config.json
{
  "changelog": "@changesets/cli/changelog",
  "commit": false,
  "fixed": [["@tutorial/*"]],
  "linked": [],
  "access": "restricted",
  "baseBranch": "main"
}

独立版本模式（Independent） ​

每个包独立维护版本号：

json
{
  "fixed": [],
  "linked": [["@tutorial/types", "@tutorial/utils"]]
}
模式优点缺点适用场景
Fixed版本一致，易于理解无变更的包也被 bump强耦合包组
Linked部分同步配置复杂中等耦合包组
Independent灵活，按需发布版本碎片化松散耦合包组

预发布与灰度 ​

创建预发布版本 ​

bash
# 进入预发布模式
pnpm changeset pre enter beta

# 创建 changeset
pnpm changeset

# 版本计算（生成 1.0.0-beta.1）
pnpm version

# 发布（带 tag）
pnpm release --tag beta

退出预发布 ​

bash
# 退出预发布模式
pnpm changeset pre exit

# 正式发布
pnpm version
pnpm release

灰度发布策略 ​

json
// package.json
{
  "publishConfig": {
    "access": "public",
    "tag": "beta" // 默认发布到 beta 标签
  }
}
bash
# 用户安装特定标签
pnpm add @tutorial/ui@beta

最佳实践 ​

1. 提交规范与 Changeset 关联 ​

bash
# Conventional Commits 与 changeset 类型映射
feat: xxx          → minor
fix: xxx           → patch
BREAKING CHANGE:   → major

2. 自动化 Changeset 生成 ​

yaml
# .github/workflows/changeset.yml
- name: Create Release Pull Request
  uses: changesets/action@v1
  with:
    version: pnpm version
    publish: pnpm release

3. 版本回滚 ​

bash
# 撤销最近一次发布
git tag -d v1.0.1
git push origin :refs/tags/v1.0.1

# 回滚代码
git revert HEAD~1

# 重新发布
pnpm release
