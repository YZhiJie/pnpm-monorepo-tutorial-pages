Node.js 版本要求 ​

最低版本：v20.0.0 ​

本仓库要求 Node.js >= 20.0.0。pnpm 9 自身的最低要求是 18.12，但 Node 18 已 EOL，且测试工具链 vitest 4 要求 Node 20+，因此仓库把 20 作为统一基线。

Node.js 版本仓库兼容性说明
< 20.x不支持Node 18 已 EOL，vitest 4 也无法运行
20.x完全兼容CI 覆盖，推荐使用
22.x完全兼容CI 覆盖，推荐使用
24.x兼容但未纳入 CI可本地开发；依赖上游补丁兼容性

版本管理器推荐 ​

nvm（Node Version Manager）

bash
# 安装 nvm
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash

# 安装并使用 Node.js 20
nvm install 20
nvm use 20

# 设置默认版本
nvm alias default 20

fnm（Fast Node Manager，Rust 编写，速度更快）

bash
# 安装 fnm
curl -fsSL https://fnm.vercel.app/install | bash

# 安装并使用 Node.js 20
fnm install 20
fnm use 20

volta（JavaScript 工具链管理器，自动切换）

bash
# 安装 volta
curl https://get.volta.sh | bash

# 安装 Node.js 和 pnpm
volta install node@20
volta install pnpm

pnpm 安装方法 ​

方法 1：npm 全局安装（最简单） ​

bash
npm install -g pnpm@9.15.4

# 验证安装
pnpm --version  # 应输出 9.15.4

方法 2：独立脚本安装（推荐 CI 环境） ​

bash
# macOS / Linux
curl -fsSL https://get.pnpm.io/install.sh | sh -

# Windows (PowerShell)
iwr https://get.pnpm.io/install.ps1 -useb | iex

方法 3：Corepack（Node.js 20 自带，部分发行版需单独启用） ​

bash
# 启用 Corepack
corepack enable

# 激活 pnpm
corepack prepare pnpm@9.15.4 --activate

# 验证
pnpm --version

方法 4：Homebrew（macOS） ​

bash
brew install pnpm

多版本共存方案 ​

场景：同时维护 pnpm 8（旧项目）和 pnpm 9（新项目） ​

方案 1：Corepack + packageManager 字段（推荐） ​

json
// package.json
{
  "packageManager": "pnpm@9.15.4"
}

Corepack 会根据该字段自动切换版本：

bash
# 首次运行会自动下载并切换到 pnpm@9.15.4
pnpm install

方案 2：npx 显式调用 ​

bash
# 使用 pnpm 8
npx pnpm@8 install

# 使用 pnpm 9
npx pnpm@9 install

方案 3：全局别名（zsh/bash） ​

bash
# ~/.zshrc 或 ~/.bashrc
alias pnpm8="npx pnpm@8"
alias pnpm9="npx pnpm@9"

# 使用
pnpm8 install
pnpm9 install

方案 4：容器隔离（Docker） ​

dockerfile
# 版本以仓库根 package.json 的 packageManager 为准：Node 20 + pnpm 9.15.4
FROM node:20-alpine

RUN corepack enable && corepack prepare pnpm@9.15.4 --activate

WORKDIR /app
COPY . .
RUN pnpm install --frozen-lockfile

要点：

  • 基础镜像用明确的 Node 20 标签，不要用 node:latest；pnpm 版本用 corepack prepare 固定，不要 npm install -g pnpm@latest。
  • 镜像里的 Node/pnpm 版本必须与 packageManager、lockfile 对应：不同主版本的 pnpm 不能互相读取 lockfile（例如 pnpm 8 与 pnpm 9），会直接报 ERR_PNPM_NO_LOCKFILE。
  • 同时维护不同 pnpm 版本的项目时，用不同的 Dockerfile/基础镜像隔离，而不是在一个镜像里装多个 pnpm。
  • 生产镜像的完整多阶段写法见 05 章：turbo prune → pnpm install → 构建 → pnpm deploy。

常见问题排查 ​

Q1: pnpm install 提示 "ERR_PNPM_UNSUPPORTED_ENGINE" ​

原因：Node.js 版本低于 package.json 中 engines 字段的要求

解决：

bash
# 查看当前 Node.js 版本
node -v

# 升级 Node.js 到 20.0.0 或更高
nvm install 20
nvm use 20

Q2: Corepack 启用后 pnpm 命令仍不可用 ​

原因：PATH 环境变量未包含 Corepack shim 目录

解决：

bash
# macOS / Linux
export PATH="$HOME/.volta/bin:$PATH"  # 或 Corepack 实际路径
corepack enable

# Windows (PowerShell 管理员模式)
corepack enable
# 重启终端

Q3: 安装时出现网络超时 "ETIMEDOUT" ​

原因：网络环境无法访问默认 registry

解决：

bash
# 切换至国内镜像
pnpm config set registry https://registry.npmmirror.com

# 或在项目 .npmrc 中配置
echo "registry=https://registry.npmmirror.com" >> .npmrc

Q4: 安装后 node_modules 结构异常（缺少依赖） ​

原因：pnpm 的严格隔离导致幻影依赖（phantom dependency）

解决：

bash
# 检查是否缺少 peerDependencies
pnpm install --strict-peer-dependencies=false

# 或显式安装缺失的依赖
pnpm add -D <missing-package>

Q5: 全局安装的 pnpm 命令找不到 ​

原因：npm 全局 bin 目录不在 PATH 中

解决：

bash
# 查看 npm 全局 bin 路径
npm config get prefix

# 将路径添加到 PATH（以 macOS 为例）
echo 'export PATH="$(npm config get prefix)/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc

检查清单 ​

  • [ ] Node.js >= 20.0.0 已安装
  • [ ] pnpm >= 9.0.0 已安装
  • [ ] pnpm --version 可正常输出
  • [ ] 国内镜像已配置（如需要）
  • [ ] 多版本共存方案已确定（如需要）
