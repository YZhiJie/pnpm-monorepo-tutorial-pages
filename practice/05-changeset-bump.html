E5 · Changesets 版本 bump ​

前置：08 版本发布与 Changesets　|　进阶：P5 Changesets 版本计算　|　习题目录：exercises/exercise-05-changeset-bump/

Changesets 的工作流是「先写 changeset 文件记录改动 → 再统一 version」。多个 changeset 可能同时命中同一个包且档位不同，changeset version 会把它们合并——同一包取最高档位，只递增一次。本练习让你实现这套版本计算。

你将实现 ​

在 src/index.ts 中实现：

ts
export type BumpType = "major" | "minor" | "patch";

export interface ChangeSet {
  releases: Array<{ name: string; type: BumpType }>;
}

/** 按 semver 规则把版本号递增一个档位。 */
export function bumpVersion(version: string, type: BumpType): string;

/** 计算所有包的新版本号（未命中的包保持原版本）。 */
export function resolveVersions(
  current: Record<string, string>,
  changesets: ChangeSet[],
): Record<string, string>;

规则 ​

bumpVersion 按 semver 递增：

bump版本变化语义
patch1.2.3 → 1.2.4向后兼容的修复
minor1.2.3 → 1.3.0向后兼容的新功能
major1.2.3 → 2.0.0破坏性变更

0.x 也按 semver 标准（如 0.5.2 的 major → 1.0.0）。

resolveVersions 的合并规则：

text
同一包被 patch + minor 命中 → 按 minor
同一包被 minor + major 命中 → 按 major
未被任何 changeset 命中的包      → 版本保持不变

档位高低：patch < minor < major。

bash
pnpm --filter @tutorial/exercise-05 test:mine   # 跑你的实现

参考答案 ​

点开查看参考实现

思路：① bumpVersion 用正则拆出三段数字，按档位改写；② resolveVersions 先扫一遍所有 changeset，为每个包记录「命中的最高档位」（用 rank 数值比较），再基于当前版本各递增一次。

ts
/** 档位高低：数值越大越「重」，用于合并多个 changeset 时取最高档。 */
const RANK: Record<BumpType, number> = { patch: 0, minor: 1, major: 2 };

export function bumpVersion(version: string, type: BumpType): string {
  const match = /^(\d+)\.(\d+)\.(\d+)/.exec(version);
  if (!match) throw new Error(`非法版本号：${version}`);

  let major = Number(match[1]);
  let minor = Number(match[2]);
  let patch = Number(match[3]);

  if (type === "major") {
    major += 1;
    minor = 0;
    patch = 0;
  } else if (type === "minor") {
    minor += 1;
    patch = 0;
  } else {
    patch += 1;
  }

  return `${major}.${minor}.${patch}`;
}

export function resolveVersions(
  current: Record<string, string>,
  changesets: ChangeSet[],
): Record<string, string> {
  const highest = new Map<string, BumpType>();

  for (const changeset of changesets) {
    for (const release of changeset.releases) {
      const existing = highest.get(release.name);
      if (!existing || RANK[release.type] > RANK[existing]) {
        highest.set(release.name, release.type);
      }
    }
  }

  const result: Record<string, string> = { ...current };
  for (const [name, type] of highest) {
    const base = current[name];
    if (base === undefined) continue;
    result[name] = bumpVersion(base, type);
  }
  return result;
}

延伸思考 ​

  • 「同一包取最高档」是有意的设计：防止某个人的 patch 被另一个人的 major 覆盖。想想如果不这样做会出什么问题。
  • 本练习只处理单包版本计算。真实 changeset version 还会：改写内部依赖范围（受 updateInternalDependencies 控制）、按 linked 组抬高水位、生成 CHANGELOG.md。对照 P5 与仓库的 .changeset/config.json，说说 linked: [["@tutorial/types", "@tutorial/utils", "@tutorial/ui"]] 会给本练习的输出带来什么额外变化。
  • 在真实仓库跑一次 pnpm changeset → 写一个 changeset → pnpm version，观察 package.json、CHANGELOG.md 与依赖范围的实际变化。
