E3 · 幻影依赖检测 ​

前置：04 依赖共享与 Hoisting 控制　|　进阶：P3 peer 解析与 hoisting 内核　|　习题目录：exercises/exercise-03-phantom-dependency/

pnpm 用严格的 node_modules 结构堵住了「幻影依赖」——即某个包引用了自己 package.json 里没声明的依赖（只是碰巧被提升上来）。本练习让你写一个静态检查器，把「声明了哪些依赖」和「代码里 import 了哪些包」做对比。

你将实现 ​

在 src/index.ts 中实现：

ts
/** Node 内置模块（裸名），已为你准备好。 */
export const NODE_BUILTINS: ReadonlySet<string>;

export interface PhantomReport {
  phantom: string[]; // 用了但没声明
  unused: string[]; // 声明了但没用
}

/** 把导入说明符归一化为包名；无法归一化（非外部包）时返回 null。 */
export function toPackageName(specifier: string): string | null;

/** 对比「声明的依赖」与「代码引用的包」，给出体检报告（两个数组按字母序排序）。 */
export function detectPhantom(
  declared: string[],
  imports: string[],
): PhantomReport;

规则与提示 ​

toPackageName 的归一化规则：

说明符结果原因
./utils、../shared/x、/abs/xnull相对/绝对路径
node:fsnullnode: 前缀内置
fs/promises、pathnull裸内置模块（查 NODE_BUILTINS）
#internal/utilnull子路径 import maps
@scope/pkg/sub@scope/pkgscoped 包取前两段
lodash/fplodash普通包取第一段

detectPhantom 的输出按字母序排序：

text
declared = ["react"], imports = ["react", "lodash", "lodash/fp"]
→ { phantom: ["lodash"], unused: [] }

declared = ["react", "lodash", "@types/node"], imports = ["react"]
→ { phantom: [], unused: ["@types/node", "lodash"] }

参考答案 ​

点开查看参考实现

思路：三步——① 归一化每个导入说明符为「包名或 null」；② 用集合做差：被引用却未声明 → phantom，已声明却未被引用 → unused；③ 排序保证结果稳定可比。

ts
export function toPackageName(specifier: string): string | null {
  if (!specifier) return null;
  // 相对路径（./ ../ . ..）与绝对路径都不是外部包
  if (specifier.startsWith(".") || specifier.startsWith("/")) return null;
  // node: 前缀显式内置
  if (specifier.startsWith("node:")) return null;
  // # 开头的子路径 import maps
  if (specifier.startsWith("#")) return null;
  // data:/http(s) 等 URL 导入
  if (specifier.includes("://") || specifier.startsWith("data:")) return null;

  const segments = specifier.split("/");
  const name = specifier.startsWith("@")
    ? segments.slice(0, 2).join("/")
    : segments[0];

  return NODE_BUILTINS.has(name) ? null : name;
}

export function detectPhantom(
  declared: string[],
  imports: string[],
): PhantomReport {
  const declaredSet = new Set(declared);
  const importedSet = new Set<string>();

  for (const specifier of imports) {
    const name = toPackageName(specifier);
    if (name) importedSet.add(name);
  }

  const phantom = [...importedSet]
    .filter((name) => !declaredSet.has(name))
    .sort();
  const unused = [...declaredSet]
    .filter((name) => !importedSet.has(name))
    .sort();

  return { phantom, unused };
}

延伸思考 ​

  • 为什么「在 npm/yarn 的扁平结构下，幻影依赖能跑起来但不该依赖」？结合 P3 的 hoisting 机制解释。
  • 用真实例子验证：在某包里 import 一个只在根 node_modules 存在的包，pnpm install 会怎么报错？这正是 pnpm 严格结构的价值。
  • 工业级实现请参考 depcheck 与 eslint-plugin-import 的 no-extraneous-dependencies 规则。
