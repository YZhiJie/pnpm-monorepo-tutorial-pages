E2 · workspace 协议语义 ​

前置：06 workspace 协议与依赖解析　|　习题目录：exercises/exercise-02-workspace-protocol/

仓库内互相依赖时，package.json 里写的是 workspace:* 这类协议。包一旦发布到 npm，pnpm 必须把它改写成真实版本范围——否则仓库外的用户装不上。本练习让你实现这套改写规则。

你将实现 ​

在 src/index.ts 中实现两个函数：

ts
export type WorkspaceProtocol = "exact" | "caret" | "tilde" | "raw" | "none";

export interface ResolvedSpec {
  isWorkspace: boolean;
  protocol: WorkspaceProtocol;
  publishedRange: string | null;
}

/** 判断依赖声明是否使用 workspace 协议（以 `workspace:` 开头）。 */
export function isWorkspaceSpec(spec: string): boolean;

/** 解析依赖声明，给出「发布时应该写出的版本范围」。 */
export function resolveWorkspaceSpec(
  spec: string,
  localVersion: string,
): ResolvedSpec;

规则 ​

设本地包版本为 localVersion = "1.2.3"：

依赖声明protocolpublishedRange说明
workspace:*exact1.2.3精确版本
workspace:^caret^1.2.3加 caret 前缀
workspace:~tilde~1.2.3加 tilde 前缀
workspace:^2.0.0raw^2.0.0显式范围，原样保留
^1.0.0none^1.0.0普通范围，原样返回
link:../utilsnonenull本地协议，无法发布

💡 只有 link: / file: / portal: 这类指向磁盘路径的协议返回 null；普通 registry 范围（如 ^1.0.0）返回原文。

参考答案 ​

点开查看参考实现

思路：先判断是否为 workspace 协议；是的话取出 workspace: 之后的「范围部分」，它只可能是四类之一：* / ^ / ~ / 显式范围。前三类是「缩写」，需结合本地版本补齐；显式范围保留原文。非 workspace 协议则区分「普通 registry 范围」与「不可发布的本地协议」。

ts
const WORKSPACE_PREFIX = "workspace:";
/** 这类本地协议指向磁盘路径，无法发布到 npm registry。 */
const LOCAL_PROTOCOLS = ["link:", "file:", "portal:"];

export type WorkspaceProtocol = "exact" | "caret" | "tilde" | "raw" | "none";

export interface ResolvedSpec {
  isWorkspace: boolean;
  protocol: WorkspaceProtocol;
  publishedRange: string | null;
}

export function isWorkspaceSpec(spec: string): boolean {
  return spec.startsWith(WORKSPACE_PREFIX);
}

export function resolveWorkspaceSpec(
  spec: string,
  localVersion: string,
): ResolvedSpec {
  if (isWorkspaceSpec(spec)) {
    const range = spec.slice(WORKSPACE_PREFIX.length);
    if (range === "*") {
      return {
        isWorkspace: true,
        protocol: "exact",
        publishedRange: localVersion,
      };
    }
    if (range === "^") {
      return {
        isWorkspace: true,
        protocol: "caret",
        publishedRange: `^${localVersion}`,
      };
    }
    if (range === "~") {
      return {
        isWorkspace: true,
        protocol: "tilde",
        publishedRange: `~${localVersion}`,
      };
    }
    return { isWorkspace: true, protocol: "raw", publishedRange: range };
  }

  const unpublishable = LOCAL_PROTOCOLS.some((prefix) =>
    spec.startsWith(prefix),
  );
  return {
    isWorkspace: false,
    protocol: "none",
    publishedRange: unpublishable ? null : spec,
  };
}

延伸思考 ​

  • 本仓库的 .npmrc 设了 save-workspace-protocol=rolling。它决定 pnpm add 时默认写入哪种 workspace 协议——对照 P3 / 第 06 章内容，说说 rolling 与 *= 的差别。
  • 把 workspace:^ 与 workspace:* 分别用在一个真实内部依赖上，跑 pnpm install 后观察：仓库内解析结果相同，但发布改写结果不同。这就是「开发体验一致、发布语义可控」的设计意图。
