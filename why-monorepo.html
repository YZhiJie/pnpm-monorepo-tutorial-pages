01 · 为什么选择 pnpm Monorepo ​

阅读时长：15 分钟　|　前置要求：会用 npm install　|　配套漫画：第 1、2 话

这是本教程的第一章。它不急着敲命令，而是先把「为什么」讲透——只有理解了痛点，后面每一行配置你才知道自己在解决什么问题，也才能在 pnpm-workspace.yaml、.npmrc 里做出自己的取舍，而不是抄一份能跑的模板。

你将学到 ​

  • npm 多项目模式下的三大痛点：磁盘浪费、幻影依赖、版本漂移
  • pnpm 的 Store + 硬链接如何一招化解它们
  • Monorepo 与 Multi-repo 的本质差异与选型标准
  • 本教程示例项目的最小可运行结构

一、先听个故事：磁盘君的眼泪 ​

漫画里的三个场景，对应 npm 时代的三个真实痛点：

漫画场景技术名词后果
每个项目各存一份 node_modules重复存储20 个项目 × 500MB ≈ 10GB 白白浪费
代码引用了未声明的包还能跑幻影依赖（Phantom Dependency）某天 hoist 结构一变，线上直接崩溃
不同项目装同一包的不同版本版本漂移lockfile 也无法跨项目对齐，升级失控

幻影依赖值得单独强调一句：它之所以「能跑」，纯粹是因为 npm 把依赖扁平化提升到了 node_modules 顶层，于是你没声明过的包也恰好躺在那里。这不是魔法，是运气——一旦依赖树变化（新增一个包、改一次版本），运气就没了。

pnpm 的解法：内容寻址 Store ​

核心思想一句话：包内容只存一份在全局 Store，项目里放硬链接。

  • 下载的包按内容哈希（SHA-512）存入全局 store（本机实测路径由 pnpm store path 给出）；
  • 项目 node_modules/.pnpm/ 里是硬链接，指向 store，不额外占用磁盘；
  • 各包的依赖用软链接精确连线，未声明的包根本摸不到 → 从结构上根治幻影依赖。

💡 类比：npm 像每家都买一套《百科全书》；pnpm 像全小区共享一个图书馆，每家手里只有借书证（链接）。

这三层结构的内部细节（虚拟存储目录怎么命名、硬链接与软链接各出现在哪里）会在原理篇 P1 里用真实目录逐一拆开。

二、光有 pnpm 还不够，还要 Monorepo ​

pnpm 解决了「装包」的问题，但如果你有多个互相依赖的项目，还要解决「协作」的问题：

维度Multi-repo（多仓库）Monorepo（单仓库多包）
代码共享发包到 registry，改动要发版才能用workspace:* 直接链本地，改动即生效
版本对齐各仓库版本号各自为政共享 lockfile，依赖版本天然对齐
原子提交跨仓库改动要拆 N 个 PR一次提交改完所有相关包
协作成本跨仓库 review、手动同步 changelog单仓库统一规范、统一 CI

pnpm + Monorepo 是天作之合：workspace 协议让「本地包互相引用」零成本，Store 让「装 100 个包」也不爆炸。这也是本教程选择 pnpm 而不是 npm/yarn 作为 Monorepo 底座的原因。

三、五分钟跑通示例项目 ​

bash
# 1. 安装（pnpm 会自动识别 workspace，一条命令装完全部子包）
pnpm install

# 2. 启动前端应用（它实时引用本地 packages/ui）
pnpm --filter @tutorial/web dev
# → Vite 启动 http://localhost:5173，页面上的按钮组件来自 packages/ui

# 3. 另开终端，启动 API（实时引用本地 packages/utils）
pnpm --filter @tutorial/api dev
# → http://localhost:3000/api/users 返回分页数据

观察这个关键片段 ​

apps/web/package.json 里：

json
{
  "dependencies": {
    "@tutorial/ui": "workspace:*"
  }
}

workspace:* 的含义是：永远链接 workspace 里的最新代码。你改 packages/ui/src/Button.tsx 保存，浏览器立刻热更新——无需发版、无需 npm link、无需版本号。

⚠️ 注意：pnpm install 只是把子包链接到位。子包若要输出编译产物（如 packages/ui 打包成 dist），需要额外跑 pnpm build。这正是后面构建章节要解决的事。

四、本教程的学习地图 ​

text
pnpm-monorepo-tutorial/
├── apps/                    # 能独立运行的应用
│   ├── web/                 # React 前端（Vite）
│   └── api/                 # Node API（Express）
├── packages/                # 被复用的共享库
│   ├── types/               # TS 类型（无运行时）
│   ├── utils/               # 工具函数
│   └── ui/                  # React 组件
├── exercises/               # 教程配套练习（可运行、有参考答案）
├── docs/                    # 本教程正文
├── pnpm-workspace.yaml      # 声明 workspace 范围（第 3 章详解）
└── .npmrc                   # pnpm 行为配置（贯穿全书）

后续四篇会沿着「会用 → 会设计 → 会工程化 → 懂原理 → 能做题」的路线推进，侧边栏即为推荐顺序。
